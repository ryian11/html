# HTML 생성기 — 진행 기록

2026-09-17 기준. CJ 중3 영어(소영순) 전자저작물에서 출발해 여러 교과서에 쓸
범용 HTML 생성 도구로 키우는 작업의 전체 기록.

---

## 1. 목적과 원칙

### 최종 목적

```
자료 → Claude가 규칙·구조 분석 → 구조화된 데이터 → 일반 프로그램이 HTML/CSS/JS 생성
```

Claude는 **규칙을 한 번 정할 때만** 부른다. 반복 생성은 프로그램이 한다.
Claude가 매번 HTML을 직접 만드는 구조로 바꾸지 않는다.

### 지켜온 규칙

| 규칙 | 왜 |
|---|---|
| 사용자가 지정한 파일·폴더만 읽는다 | 03_PDF·04_피드백·05_QR 등을 멋대로 열지 않는다 |
| 검증된 생성 로직은 최소로만 고친다 | 1~8단원이 이미 실기에 나가 있다 |
| 고칠 때마다 회귀 검사 | 7·8단원 산출물 19개가 바이트 단위로 같은지 |
| 개발물에는 완성본만 | 백업·측정값·중간 산출물은 작업 영역으로 |
| 단원 수·쪽 이름·폴더명을 코드에 박지 않는다 | 교재마다 다르다 |

## 2. 구조 — 3층

```
① 자료 층   사용자가 고른 파일·폴더              settings.json · project.json
② 규칙 층   이 교재를 어떻게 읽고 조립하는가
   ②-a 절차  문장 분해 · 한국어 정렬 · CSS 계산   → 코드 (read_*.py)
   ②-b 값    시트 이름 · 열 위치 · 팝업 번호       → rules.json
③ 단원 층   data<N>.py · layout<N>.json · 잰 값   단원마다 바뀜
```

②-a와 ②-b를 가르는 기준은 **다른 교재에 가져갔을 때 무엇이 바뀌는가**이다.
문장을 나누는 절차는 그대로지만 시트 이름은 바뀐다.
코드에 있는 것을 전부 JSON으로 옮기지 않는다 — HTML 템플릿, 퀴즈 판정,
한국어 분해, CSS 생성은 일부러 코드에 남긴다.

### 파이프라인

```
추출 extract   자료(xlsx·PDF) → 단원자료/data<N>.py        read_import.py
생성 build     data<N>.py     → html·css·js·popup         read_gen.py
측정 measure   실기 폴더를 브라우저로 재기 → 잰 값 3종     read_measure.py
검증 verify    형식·원고 대조·이미지·scrollTop            read_verify.py
```

`runner.py` 가 이 넷을 부르고, `recipes/cj_reading.py` 가 "무엇을 어떻게"를 안다.
`app.py`·`app_page.py` 가 화면이다. **runner 는 Reading 도 딕테이션도 모른다.**

## 4. 지금까지 한 것

### 4.1 1차 생성기

두 번 눌러 실행하는 `HTML생성기.vbs` → 로컬 서버(`app.py`) → 브라우저 화면.
파이썬 기본 모듈만 쓴다. 자료 경로를 고르고 단원을 골라 [생성]을 누르면
추출→생성→측정→검증이 돌고 미리보기가 뜬다.

### 4.2 프로토 분석 (rules.json)

견본 단원의 페이지를 읽어 "다른 단원에도 그대로 쓰는 것"만 뽑는다.

```
rules/<레시피>/proto_L6.json   프로토 분석 결과 — 기계가 씀
rules/<레시피>/rules.json      확정된 규칙 — 사람이 승격시킨 것만
```

**이 단계의 rules.json 은 생성에 쓰이지 않는다.** 코드와 견주어 보여 줄 뿐이다.
6단원 대조 결과: `같음 30 · 다름 0 · 규칙에만 3 · 프로토로는 모름 3`.
손으로 만든 6단원 원본과 생성기 산출물이 견줄 수 있는 규칙 30개에서 전부 일치.

대조할 때 코드 쪽 값은 소스를 뜯지 않고 **회귀 기준본에 저장된 실제 생성 결과**를
프로토와 똑같은 함수로 읽는다. 그래야 두 값이 같은 자로 잰 값이 된다.

### 4.3 A — 설정 패널

`layout<N>.json` 을 화면에서 고친다.

| 칸 | layout 열쇠 | 하는 일 |
|---|---|---|
| 문단 나눔 | `paras` | 한 줄이 한 문단, 쉼표로 문장 번호 |
| 문단 첫머리 | `prefix` | 마이크 아이콘 / 말하는 이 (CSS로 붙음) |
| 문장 — 왼쪽 | `text` | 지면과 다른 글자. 고친 칸만 저장 |
| 문장 — 오른쪽 | `kr` | 해석 |
| 쪽 CSS | `css` | 문단 위치·너비·여백 |
| 말하는 이 이름 | `speaker` | 단원 공통 |
| 뺀 문장 | `drop` | 되살리기 |
| 이미지 크기 | `img` | 잰 값 · 읽기 전용 |

CSS는 칸을 쪼개지 않고 그대로 보여 준다. 쪽마다 `::before` 띄움 상자나
`nth-of-type` 예외가 붙어 있어(7단원 p125_01) 틀에 가두면 오히려 못 고치게 된다.

### 4.4 B — 쪽만 골라 생성

`read_gen.build(lesson, out, only={'p123_01'})` 두 줄이 전부다.
`only=None` 이면 예전과 바이트 단위로 같다.

```
ctx.pages → runner.run(pages=) → 레시피 build → read_gen.build(only=)
```

**쪽 하나를 처음부터 생성하는 입구가 여기다.** 나중에 프로토 기반 생성을 붙일 때도
같은 입구를 쓴다 — 달라지는 것은 data<N>.py 를 무엇으로 채우느냐뿐이다.

막는 것이 두 겹이다. 생성 단계가 고른 쪽만 쓰고, 그래도 달라진 것이 있으면
방금 뜬 백업에서 되돌린다.

단원 공통 파일(들머리 쪽·전체듣기 팝업·예시답안)은 단원 전체에서 나오므로
한 쪽만 고쳐도 함께 새로 쓴다.

측정은 언제나 **단원 전체**를 잰다. `write_scrolls` 가 쪽 목록 전체를 새로 쓰기
때문에 한 쪽만 재면 나머지 쪽의 값이 지워진다.

### 4.5 4·5·6 — 정리와 일반화

**백업 위치** `lesson08/ops/_backup/` → `_backup/산출물/<레시피>/<단원>/<날짜시각>/`.
되돌리기는 예전 자리도 함께 본다. 개발물에 남아 있던 부스러기 23개도 옮겼다.

**project.json** — 단원 목록을 사용자가 지정한 두 폴더에서만 찾아 적어 둔다.
한 번 적힌 뒤로는 이 파일이 기준이고 사람이 고칠 수 있다.

```json
{"cj_reading": {"units": [
  {"id":"7","name":"7단원","storyboard":"…Lesson 7.xlsx","ops":"…lesson07/ops","sheet":"7과"},
  {"id":"special_lesson","name":"Special Lesson","sheet":"SL","guide":"…각론9….pdf"}
]}}
```

경로는 프로젝트 폴더 기준 상대 경로라 다른 PC로 옮겨도 그대로 쓴다.

**폴더 정리** — 실제 import 를 전부 추적해 아무도 부르지 않는 것만 옮겼다. 지우지 않았다.

### 4.6 Special Lesson 실전

1~8단원과 다른 점이 여럿 드러났고, 전부 **자료를 보고 스스로 판단**하게 고쳤다.

| 판단 | 근거 | 1~8단원 | Special Lesson |
|---|---|---|---|
| 들머리 쪽(Read Smart)을 만들까 | 녹음 대본에 `readsmart` 코너가 있나 | 만듦 | 안 만듦 |
| 리딩 퀴즈를 낼까 | 문제 코너가 있나 | 냄 | 안 냄 |
| 딕테이션 단추를 낼까 | 스토리보드에 `Dictation` 시트가 있나 | 냄 | 안 냄 |
| 본문 첫 쪽 이름 | `images/` 에 어느 폴더가 있나 | `_02` | `_03` |
| 녹음 대본 시트 | project.json | `7과` | `SL` |
| 화자 표기 | `W1(Teacher):` 꼴이면 지움 | 해당 없음 | 지움 |

**화자 표기**는 녹음 대본이 성우에게 주는 표시지 교과서 글이 아니다.
`W1(Teacher): "Good morning!"` → `"Good morning!"`,
`"Am I a dancer?" W: thought Diana.` → `"Am I a dancer?" thought Diana.`

**딕테이션 팝업 파일은 이 레시피가 만들지 않는다.** 딕테이션 작업에서 따로 만들어
그 폴더에 넣은 것이고 리딩 쪽은 가리키기만 한다. Special Lesson은 원본 자료에
딕테이션이 없어 단추만 덩그러니 있었다.

**쪽 수는 원래 상관이 없다.** 1~8단원 4쪽, Special Lesson 6쪽 — 생성기는 목록을
그대로 훑는다. 달랐던 것은 쪽 수가 아니라 코너 구성이었다.

결과: 화면에서 [생성]을 눌러 나온 25개 파일이 바이트 단위로 같다. 검증도
형식·원고 대조·이미지·scrollTop 전부 OK.

## 5. 고친 버그 — 기록해 둘 만한 것

### 5.1 미리보기에 글자가 하나도 안 나옴

`include/js/components.js` 가 `location.pathname` 에서 `ops` 를 찾아 handlebars 경로를
계산한다. 미리보기 URL에 `ops` 가 없으면 `../../../../include/js/handlebars.js` 로 튀어
404가 되고, handlebars가 없으면 `comp-language-target` 이 변환되지 않아 글자가 안 나온다.
→ 미리보기 URL을 `/files/<레시피>/<단원>/ops/<파일>` 로 `ops` 를 한 칸 끼워 넣었다.

### 5.2 측정값이 아무 데서도 읽히지 않았다

`read_gen.load_lesson` 은 `scrolls<N>` 을 **모듈로** 읽는데(생성기 폴더),
레시피는 산출 폴더에 쓰고 있었다. 러너로 [측정]을 돌려도 반영된 적이 없었다.
7·8단원이 멀쩡했던 것은 그때 측정을 `read_run.py` 로 따로 돌렸기 때문.
→ `gen_dir` 을 바로잡고, 덮어쓰기 전 `_backup/measure/` 에 남기게 했다.

### 5.3 data<N>.py 가 캐시에 남았다

`load_lesson` 은 `import_module` 을 쓴다 — reload가 아니다. 화면이 떠 있는 동안
[추출]이 새 파일을 써도 예전 모듈을 계속 썼다. **설정 패널에서 고치고 재생성해도
반영되지 않았다.** CLI는 매번 새 프로세스라 드러나지 않던 버그.
→ 레시피에 `fresh(unit)` 을 두어 쓰는 쪽에서 먼저 다시 읽게 했다.

### 5.4 묵은 .pyc — `build() got an unexpected keyword argument 'only'`

파이썬은 원본의 (수정시각, 크기)가 `.pyc` 에 적힌 것과 같으면 `.py` 를 아예 읽지 않는다.
연결된 폴더는 수정시각이 흔들려서, 원본을 고쳐도 묵은 `.pyc` 를 계속 쓰는 일이 생긴다.
실제로 `read_gen.pyc` 만 재컴파일되지 않아 옛 `build()` 가 불렸다.
→ `runner.py` 가 새 `.pyc` 를 만들지 않고(`sys.dont_write_bytecode`), 시작할 때와
레시피를 부를 때마다 어긋난 `.pyc` 를 치운다. 지울 수 없으면 앞머리를 지운다.
`app.log` 에 시작할 때마다 실제로 불려 온 파일과 `build()` 모양이 남는다.

### 5.5 제목 없는 쪽에서 측정이 멈춤

`read_measure.py` 가 `p['title']['kr']` 을 그대로 집었다. 7·8단원은 첫 쪽에만 제목이
있어 둘째 쪽에서 `TypeError`. 6단원만 측정이 되고 7·8단원은 안 되는 상태였다.
회귀 검사가 `build` 단계만 다시 뽑기 때문에 측정 단계는 검사 범위 밖이었다.
→ 두 곳(`arr` 과 `_title_images`)에 조건을 달았다. 제목 있는 쪽 결과는 그대로.

### 5.6 쪽 선택이 생성 뒤 풀림

`poll()` 이 끝에 `loadPages()` 를 불러 쪽 목록을 다시 그리면서 체크가 전부 풀렸다.
한 번 돌린 뒤 [생성]을 다시 누르면 단원 전체가 생성됐다.
→ 고른 쪽을 기억하고, 목록을 다시 그릴 때 있는 쪽만 남겨 되살린다.
버튼 글자도 범위 그대로 바뀐다 — `[1쪽 생성]` · `[7단원 전체 생성]`.

### 5.7 미니 단어장 묶음이 밀림

미니 단어장 묶음은 시트에서 빈 줄로 나뉘어 오고 **낱말이 있는 쪽에만** 있다.
자리 번호로 세면 낱말 없는 쪽이 끼었을 때 하나씩 밀린다.
또 `turn on` 이 본문의 `turned on` 과 안 맞아 154쪽이 비면서 뒤가 밀렸다.
→ 낱말 있는 쪽에만 묶음을 배정하고, 구동사는 앞말이 변하는 것을 규칙에 더했다.

### 순서를 한 번 고쳤다

처음 매긴 번호는 "지금 불편한 순서"였다. 목적(범용 도구) 기준으로 두 군데를 바꿨다.

* **C(규칙 승격)보다 D(두 번째 레시피)가 먼저.** `rules.json` 의 항목은 레시피
  하나에서만 뽑은 것이다. 무엇이 진짜 공통인지는 딕테이션·동아영어를 붙여 봐야
  드러난다. 한 레시피만 보고 스키마를 확정하면 다시 뜯게 된다.
* **지면 다듬기는 개발 순서가 아니다.** 설정 패널에서 사용자가 지면을 보며 하는 일.

```
[끝] 1  자료 지정 칸          화면에서 project.json 을 고친다
[끝] 2  회귀 검사 빈틈        측정 단계도 검사한다
[끝] -  백업 자동 정리        단원마다 최근 5벌
```

### 1 · 2 · 백업 정리 — 끝난 것

**자료 지정 칸** — ①자료 아래 `단원별 자료` 를 펼치면 단원마다 **녹음 대본 시트
이름**과 **지도서 PDF** 를 화면에서 고친다. 없는 파일을 적으면 칸이 붉어진다.
`project.json` 을 사람이 파일로 열 일이 없어졌다.

**회귀 검사 빈틈** — 이제 `build` 뿐 아니라 **측정까지** 검사한다.
같은 로직을 검사 쪽에 베껴 두면 진짜 코드가 바뀌어도 못 잡으므로,
`read_measure.measure()` 를 **그대로 부르고 브라우저만 대역**으로 세운다.
잰 값은 임시 폴더로 보내 실제 파일은 건드리지 않는다.
일부러 제목 조건을 빼고 돌려 보니 `TypeError` 를 잡아냈다 — 5.5의 결함이
이제는 회귀 검사에서 걸린다.

**백업 자동 정리** — 산출물·layout·측정값 백업 모두 최근 5벌만 남긴다
(`runner.KEEP_BACKUPS`). 지우기가 막힌 곳에서는 조용히 넘어간다.

### 남은 우선순위

**3 — 각론9 해석 추출 (규칙으로 내리기)**

지시문 줄을 걸러내고 단 경계에서 문장을 잇는 규칙을 더한다. 그러면 Special Lesson
해석이 버튼으로 나오고, 지금 손으로 넣은 layout 파일은 **검산용 정답지**가 된다 —
추출 결과가 그것과 같으면 규칙이 맞은 것. 이 검산이 가능한 것이
"손으로 먼저, 규칙은 나중" 순서로 한 덕이다.

**4 — 두 번째 레시피 (D)**

`rules.json` 을 실제 생성에 쓴다. 한 항목씩 옮기고 매번 회귀 검사.
항목 하나를 옮기고 7·8단원이 그대로면 확정, 아니면 되돌린다.

두 번째·세 번째 교재 유형을 붙여야 "범용"이 증명된다. 그때 공통 부분도 드러난다.

```
sheet_io.py   엑셀 읽기 (rich_text 밑줄, 병합셀, 헤더 건너뛰기)
html_io.py    CRLF·끝 개행 없음으로 쓰기, 바이트 비교
mp3_io.py     파일명 변환 + 실제 파일 확인
```

지금은 `read_import.py` 안에 있다. 꺼내는 순간 7·8단원 경로를 건드리게 되므로,
새 레시피에서 먼저 쓰고 동작을 확인한 뒤 리딩을 옮기는 순서가 안전하다.

**5 — 규칙 승격 (C)**

`rules.json` 을 실제 생성에 쓴다. 한 항목씩 옮기고 매번 회귀 검사.
항목 하나를 옮기고 7·8단원이 그대로면 확정, 아니면 되돌린다.
D 로 스키마가 확정된 뒤에 한다.

### 언젠가 — data<N>.py 를 JSON 으로

`data<N>.py` 는 데이터가 아니라 실행되는 파이썬 코드다. 5.3·5.4의 캐시 사고가
그 대가였다. `layout<N>.json` 은 JSON이라 그런 문제가 없다.
최종 방향에서는 Claude가 분석 결과를 파일로 내놓게 되는데, **파이썬 소스를 생성하게
두는 것보다 JSON을 내놓게 하는 쪽이 안전하다.** 지금 당장 막고 있지는 않으므로
`layout_io` 가 `.py` 와 `.json` 을 둘 다 읽게 해 둔 것처럼 한 단원씩 옮긴다.

## 8. 회귀 검사

```
py regress.py save  cj_reading 7 8     지금 결과를 기준본으로
py regress.py check cj_reading         기준본과 견주기
```

임시 폴더에 `build` 단계만 다시 돌려 바이트 단위로 비교한다. 실기 폴더는 건드리지 않는다.
화면 왼쪽 맨 아래 [기준본과 견주기] / [지금 결과를 기준본으로] 도 같은 일을 한다.

**이 작업 내내 모든 고침 뒤에 이걸 돌렸고, 7·8단원 19개는 한 번도 달라지지 않았다.**
(측정을 새로 돌려 scrollTop 이 갱신된 두 번은 제외 — 그때는 확인 후 기준본을 갱신했다.)

~~빈틈: 측정 단계가 검사 밖~~ → 메웠다. 이제 단원마다 `measure()` 를
