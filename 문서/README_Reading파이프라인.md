# 0. 큰 그림 — 뭘 사람이 하고 뭘 기계가 하나

```
        사람이 쓰는 것                 기계가 쓰는 것
        ─────────────                 ─────────────
        data<N>.py       ──┐       ┌── scrolls<N>.py     (본문 scrollTop)
        (원고·번호·레이아웃) │       │   popscroll<N>.py   (팝업 scrollTop)
                           ├─ 생성 ─┤   krlayout<N>.py    (해석 줄 배치)
        스토리보드 엑셀   ──┘       │
        (미니단어장·구문해설)        └── lesson<NN>/ops/*  (최종 결과물)
```

* **원고와 번호·레이아웃 숫자는 사람이** `data<N>.py` 한 파일에 적습니다.
* **미니 단어장과 구문 해설은 안 적습니다.** 스토리보드 엑셀에서 자동으로 읽습니다.
* **scrollTop·해석 줄 위치는 안 적습니다.** 크롬에 실제로 띄워 재서 자동으로 씁니다.

그래서 새 단원 한 개가 이렇게 끝납니다.

> 원고 옮겨 적기 → `python read_run.py 7` → 화면 보고 CSS 숫자 몇 개 조정 → 다시 돌리기

### PAGES — 페이지별 원고

```python
PAGES = {
 'p118_02': dict(
   num='118',                 # 쪽 번호. mp3 이름과 구문해설 엑셀 조회에 씁니다
   qbtn='Q1',                 # readingQuiz 버튼 라벨
   title=dict(
     src='3_118_read_00',     # 제목 mp3 (대시→언더바·소문자로 자동 변환)
     en='Easy and Fast, but Be Careful!',
     kr='쉽고 빠르지만 조심해라!',
     cls='mainTitle',         # mainTitle / subTitle sTit01 … sTit04
     mark='',                 # 제목 이미지 위 단어 버튼이 있으면 '[mark:1: ]'
   ),
   blocks=[
     ('para', [
       ('01', '영어 문장', '한글 해석'),      # ('mp3 뒷번호', 영어, 한글)
       ('02', '...', '...'),
     ]),
     ('subtit', dict(src='3_118_read_07', en='...', kr='...',
                     cls='subTitle sTit04', mark='[mark:1: ]')),
     ('para', [ ... ]),        # 문단이 여러 개면 ('para', [...]) 를 여러 번
   ],
   quiz=dict(kind='input', label='Q1',
     q='What should we do ...?',  qkr='해석x',
     a='We should ...',           akr='해석x',
     qsrc='3_118_question_02', asrc='3_118_question_03'),
 ),
}
```

`mp3 뒷번호`는 `3_118_read_01.mp3` 의 `01` 입니다. 실제 녹음 파일명과 **반드시** 맞춰야 합니다.
번호를 짐작해서 넣지 마세요 — 없으면 검증에서 잡힙니다.

### 본문 표기법

| 쓰는 법 | 나오는 것 |
|---|---|
| `\|3\|` | 구문 해설 팝업 버튼 (pop 5). 문장 **맨 앞**에 붙입니다 |
| `[mark:2: dramatic]` | 미니 단어장 버튼 + 밑줄 (pop 6) |
| `[mark:1: ]` | 글자 없는 버튼. 제목이 **이미지**일 때 씁니다 |
| `<mark>…</mark>` | 버튼 없는 강조만 |
| `<br>` | 줄바꿈 |

* `[mark:n]` 번호는 **페이지마다 1부터 연속**이어야 합니다. 엑셀 `미니 단어장` 시트의
  **빈 줄로 나뉜 묶음 순서**가 곧 `ORDER` 의 페이지 순서이고, 묶음 안의 줄 순서가 `n` 순서입니다.
* `|n|` 번호도 페이지마다 1부터. 엑셀 `구문 해설` 시트에서 `num` 과 같은 쪽 번호 줄을 순서대로 가져옵니다.
* 단어가 **제목 이미지 안**에 있으면 본문이 아니라 `title.mark` 에 `[mark:1: ]` 로 넣고,
  위치는 아래 `WORDBTN` 으로 잡습니다.
* 어느 단어가 어디 들어가는지는 **스토리보드 엑셀에 박힌 교과서 지면의 빨간 네모가 기준**입니다.

### ORDER — 페이지 순서

```python
ORDER = ['p118_02','p119_01','p120_01','p121_01']
```

`_01` 인트로(Read Smart) 페이지는 여기 안 넣습니다. `ORDER[0]` 의 쪽번호로 자동으로 만듭니다
(`p118_02` → `p118_01`).

### IMG — 배경·제목 이미지 원본 크기

```python
IMG = {
 'p118_02': dict(bg=(2560,3016), title=(1600,596)),
 'p119_01': dict(bg=(2560,3172), s1=(1764,144)),
 'p121_01': dict(bg=(2560,3464), s3=(1856,152), s4=(1724,110)),
}
```

png 원본 픽셀을 그대로 적습니다. CSS 에서 `calc(2560px/2)` 로 반 크기로 씁니다.
`bg` = `read_bg.png`, `title` = `title.png`, `s1~s4` = `s_title01.png ~ s_title04.png`.

### WORDBTN — 제목 이미지 위 단어 버튼 위치

```python
WORDBTN = {
 'p118_02': [],
 'p119_01': [(224, 10)],   # (left, top)
}
```

`title.mark` 에 `[mark:1: ]` 를 넣은 페이지만 값이 필요합니다.
**처음에는 빈 `[]` 로 두고 한 번 돌리면** 측정기가 후보값을 찍어 줍니다(③ 참고).

### CSS_LAYOUT — 페이지별 추가 CSS

문단이 배경 그림의 어디에 앉을지를 정합니다. **눈으로 보고 고치는 유일한 곳**입니다.

```python
CSS_LAYOUT = {
 'p119_01': '''
.mainContent .ParagraphBox { margin-top: 40px; }
.mainContent .ParagraphBox .Paragraph { width: 1010px; }
.mainContent .ParagraphBox .Paragraph:nth-of-type(2) { margin-top: 30px; }
''',
}
```

자주 쓰는 것

| 하고 싶은 것 | 쓰는 것 |
|---|---|
| 본문 전체를 아래로 | `.ParagraphBox { margin-top: 430px; }` |
| 줄 길이 줄이기 | `.Paragraph { width: 1010px; }` |
| 문단 사이 띄우기 | `.Paragraph:nth-of-type(2) { margin-top: 30px; }` |
| 첫 줄만 들여쓰기 | `.Paragraph:nth-of-type(1) { padding-left: 250px; }` |
| 소제목을 배경 특정 자리에 | `.subTitle.sTit04 { position:absolute; left:172px; top:868px; margin:0; }` |

⚠ **문단 상자가 2개 이상인 페이지**(소제목이 중간에 또 나오는 p107_01 같은)는
reading.css 가 `.ParagraphBox { position:absolute }` 라 두 상자가 겹칩니다. 반드시

```css
.mainContent .ParagraphBox { position: relative; }
```

로 풀어 줘야 합니다.

측정이 끝나면 두 가지를 봅니다.

배경 그림 위에 글이 제대로 앉았는지 봅니다. 어긋나면 `CSS_LAYOUT` 만 고치고

# 3. 파일 구실

| `read_verify.py` | — | 검증 |

# 5. 정해 둔 값

`read_measure.py` 맨 위에 있습니다.

```python
SAFE_BODY = 40   # 본문: 위 '본문 전체 듣기' 버튼을 피하는 여유
SAFE_POP  = 20   # 팝업 여유
```

* 스크롤 상자 높이 — 본문 633 / 해석 팝업 589 / 전체듣기 팝업 549
* 해석은 **문장마다 그 문장의 영어가 시작하는 x 아래**에서 시작하고, 자리가 모자랄 때만 아래로 내려갑니다

  7 readingQuiz(마지막 쪽은 9) · 8 thinkabout · 10 missionclear · 11 예시답안

# 6. 잘 안 될 때

| 증상 | 까닭 / 할 일 |
|---|---|
| `건너뜀 — playwright 가 없습니다` | `pip install playwright && playwright install chromium` |
| `scrollTop 이 하나도 없음` | 측정을 안 돌렸습니다. `--no-measure` 를 뺐는지 보세요 |
| `mark … ≠ wordData …` | `[mark:n]` 번호가 엑셀 미니 단어장 묶음과 개수·순서가 안 맞습니다 |
| `본문 불일치` | 생성물과 `data<N>.py` 가 다릅니다. `ops` 를 손으로 고쳤다면 그 수정을 `data<N>.py` 에 옮기세요 |

| 겹침/넘침 경고 | 해석이 너무 길어 자리를 못 잡은 것. `GAP_KR` 을 줄이거나 그 문장만 `<br>` 로 끊습니다 |

| 고친 게 반영이 안 됨 | 브라우저 캐시. 새로고침(Ctrl+F5) 하거나 `_backup` 말고 `ops` 를 보고 있는지 확인 |
