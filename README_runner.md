# runner.py — 생성기 껍데기

검증된 기존 스크립트를 **그대로 부르는** 얇은 껍데기입니다.
`runner.py` 는 Reading 도 딕테이션도 모릅니다. `recipes/` 안의 레시피가 선언한 것만 실행합니다.

```
runner.py            ① 추출 → ② 생성 → ③ 측정 → ④ 검증 을 순서대로
settings.json        자료 경로 (한 번 정하면 저장됨)
recipes/
  cj_reading.py      CJ 중3 Reading 본문  ← 지금 있는 것
  cj_dictation.py    (다음)
  donga_listening.py (다음)
```

## 쓰는 법

```
py runner.py                          레시피 목록
py runner.py cj_reading               받는 자료와 고를 수 있는 단원
py runner.py cj_reading 7             7단원 전체 (추출→생성→측정→검증)
py runner.py cj_reading 7 8           여러 단원
py runner.py cj_reading 7 --steps build,verify      일부 단계만
py runner.py cj_reading 7 --out C:\temp\t7          딴 데 뽑기 (실기 안 건드림)
py runner.py cj_reading --set root=E:\00_works\2026\2026_cj_midd3_eng
py runner.py cj_reading 7 --restore 20260916_1030   백업에서 되돌리기
```

`--set` 으로 정한 경로는 `settings.json` 에 저장되어 다음에 다시 안 물어봅니다.
슬롯에 없는 폴더는 프로그램이 열지 않습니다.

## 실기에 쓸 때

`--out` 없이 돌리면 `lesson<NN>/ops` 에 바로 씁니다.
**덮어쓰기 전에 `ops/_backup/<날짜시각>/` 로 자동 백업**하고, `--restore` 로 되돌립니다.

## 레시피 만들기 (새 작업을 붙일 때)

`recipes/<이름>.py` 하나만 추가하면 됩니다. 없는 단계는 그냥 건너뜁니다.

```python
NAME  = "작업 이름"
SLOTS = [('root', '프로젝트 폴더', 'dir'), ...]   # UI 가 물어볼 것
EDIT  = [('layout{n}.json', 'layout')]           # UI 가 고칠 수 있는 파일

def setup(ctx):            # 슬롯 경로를 기존 스크립트에 꽂기
def units(ctx):            # 고를 수 있는 단원
def out_dir(ctx, unit):    # 산출 폴더
def outputs(ctx, unit):    # 백업 대상 (상대 경로)
def extract(ctx, unit):    # ① 원고 → 데이터
def build(ctx, unit):      # ② 데이터 → HTML
def measure(ctx, unit):    # ③ 브라우저 측정 (없으면 생략)
def verify(ctx, unit):     # ④ 검증 — False 면 실패
def preview(ctx, unit):    # 미리보기할 파일 목록
```

**기존 스크립트를 고치지 않고 붙는지**가 이 구조의 시험입니다.

## 확인된 것

```
│   [자료 경로 저장] │  │ 생성된 페이지를 실제로  │   │
│ ② 단원            │  │ 그대로 렌더             │   │
│   ☑7단원 ☐8단원   │  └───────────────────────┘   │
│ ③ 단계            ├───────────────────────────────┤
│   ☑추출 ☑생성     │  진행 기록 / 검증 결과         │
│   ☑측정 ☑검증     │                               │

└───────────────────┴───────────────────────────────┘
```

- **자료 경로**는 한 번 저장하면 `settings.json` 에 남습니다. `[찾아보기]` 는
  **고른 폴더 한 단계만** 보여 줍니다(재귀 탐색 없음).
- **생성**은 산출 폴더에 바로 쓰고, 덮어쓰기 전에 `_backup/<날짜시각>/` 으로 저장합니다.
- **미리보기**는 산출 폴더에서 그대로 서빙하므로 `include/`·`images/` 가 붙어
  실기와 같은 모습으로 보입니다.
- 자료 경로가 잘못돼 있으면 **생성 전에 막습니다.** 없는 폴더에 조용히 만들어 쓰지 않습니다.

## 여는 법 — 두 번 누르기

```
HTML생성기.vbs      ← 이걸 두 번 누르세요
```

검은 cmd 창이 뜨지 않습니다. 잠깐 뒤 브라우저에 화면이 열립니다.

- 바탕화면에 두고 쓰시려면 이 파일을 **마우스 오른쪽 → 바로 가기 만들기** 해서
  바로 가기를 바탕화면으로 옮기세요. 이름과 아이콘도 바꿀 수 있습니다.
- **끄는 법**: 화면 오른쪽 위 **[끝내기]**. (창만 닫으면 뒤에서 계속 돌고 있습니다)
- 두 번 눌러도 창이 두 개 뜨지 않습니다. 이미 떠 있으면 그 화면을 다시 엽니다.
- 잘 안 뜨면 같은 폴더의 **`app.log`** 를 보세요. 파이썬을 못 찾으면 안내 창이 뜹니다.

`py app.py` 로 여는 방법도 그대로 됩니다(문제가 있을 때 메시지를 보려면 이쪽이 낫습니다).

## 프로토 (견본) 분석

견본으로 삼을 단원의 페이지를 읽어, 다른 단원에도 그대로 쓰는 규칙만 뽑아 둡니다.
**이 단계에서 뽑은 규칙은 생성에 쓰이지 않습니다.** 코드와 견주어 보여 줄 뿐입니다.

화면 왼쪽 ② 프로토 에서:

1. 프로토 단원에 `6` 을 적고 [견본 쪽 불러오기]
2. 견본으로 삼을 쪽을 고르고 [프로토 분석] → `rules/cj_reading/proto_L6.json`
3. 결과를 보고 [승격] → `rules/cj_reading/rules.json`
4. [코드와 대조] → 지금 생성기가 내놓는 값과 견줍니다

명령줄로도 됩니다.

    py runner.py cj_reading --proto 6 --list          견본 쪽 목록
    py runner.py cj_reading --proto 6                 전부 분석
    py runner.py cj_reading --proto 6 --pages p105_01,p107_01
    py runner.py cj_reading --promote 6 --fresh       rules.json 으로
    py runner.py cj_reading --compare                 코드와 대조

대조 결과의 갈래:

| 갈래 | 뜻 |
|---|---|
| 같음 | 견본과 생성기가 맞음 |
| 다름 | **눈으로 확인할 것** |
| 규칙에만 | 견본에서 새로 본 것 |
| 코드에만 | 견본에서 찾지 못한 것 |
| 적어 둔 것 | 규칙이 아닌 사실 (`info.*`) |
| 프로토로는 모름 | HTML 에 안 나오는 값 (측정 여백) |

## 회귀 검사

생성기를 고칠 때마다 돌립니다. 임시 폴더에 다시 뽑아 바이트 단위로 견줍니다.
실기 폴더는 건드리지 않습니다.

    py regress.py save  cj_reading 7 8     지금 결과를 기준본으로
    py regress.py check cj_reading         기준본과 견주기

화면 왼쪽 맨 아래 [기준본과 견주기] / [지금 결과를 기준본으로] 도 같은 일을 합니다.
`save` 는 방금 뽑은 것과 실기 폴더도 함께 견주어, 손으로 고친 자국이 있으면 알려 줍니다.

## 설정 패널 — 고치고 그 쪽만 다시 뽑기

오른쪽 위 **[설정]** 을 누르면 `layout<N>.json` 을 화면에서 고칠 수 있습니다.

| 칸 | layout 열쇠 | 하는 일 |
|---|---|---|
| 문단 나눔 | `paras` | 한 줄이 한 문단, 쉼표로 문장 번호 |
| 문단 첫머리 | `prefix` | 마이크 아이콘 / 말하는 이 (CSS 로 붙습니다) |
| 문장 — 왼쪽 | `text` | 지면과 다른 글자. **고친 칸만** 저장되고 노랗게 표시됩니다 |
| 문장 — 오른쪽 | `kr` | 해석. `해석x` 는 붉게 |
| 쪽 CSS | `css` | 문단 위치·너비·여백 (`margin-top` · `width` · `margin-left`) |
| 말하는 이 이름 | `speaker` | 단원 공통 |
| 뺀 문장 | `drop` | 되살리기 |
| 이미지 크기 | `img` | 잰 값 · 읽기 전용 |

[설정 저장] 은 layout 파일에만 씁니다. HTML 에 반영하려면 재생성해야 합니다.
고치기 전 layout 파일은 `_backup/layout/` 에 날짜시각으로 남습니다.

### 이 쪽만 재생성

쪽마다 있는 [이 쪽만 재생성] 은 이렇게 돕니다.

1. 산출 폴더를 `_backup/날짜시각` 으로 백업
2. **늘 하던 경로 그대로** 단원 전체를 다시 뽑음 (추출 → 생성 → 측정 → 검증)
3. 고르지 않은 쪽 파일을 백업에서 되돌림

측정은 실기 폴더의 진짜 이미지·글꼴 위에서 해야 맞는 값이 나오므로 임시 폴더에 뽑지 않습니다.
고르지 않은 쪽은 **바이트 하나 바뀌지 않습니다.**

단원 공통 파일(들머리 쪽 · 전체듣기 팝업 · 예시답안)은 단원 전체에서 나오므로
한 쪽만 고쳐도 함께 새로 씁니다. 되돌리지 않습니다.

끝나면 새로 쓴 파일 · 되돌린 파일 · 그대로인 파일 수가 기록창에 나옵니다.

## 쪽만 골라 생성

왼쪽 **④ 쪽** 에서 고르고 [생성] 을 누르면 그 쪽만 뽑습니다. 비워 두면 단원 전체입니다.
쪽을 고를 때는 단원을 하나만 고르세요.

    py runner.py cj_reading 7            단원 전체
    (쪽 고르기는 화면에서)

고르지 않은 쪽 파일은 **열지도 쓰지도 않습니다.** 생성 단계(`read_gen.build` 의 `only`)에서
아예 걸러 냅니다. 설정 패널의 [이 쪽만 재생성] 은 여기에 더해 백업 되돌리기까지 두 겹입니다.

늘 함께 새로 쓰는 것: 들머리 쪽 · 전체듣기 팝업 · 예시답안.
단원 전체 자료에서 나오므로 한 쪽만 고쳐도 같이 바뀌어야 앞뒤가 맞습니다.

측정은 언제나 **단원 전체**를 잽니다. `write_scrolls` 가 쪽 목록 전체를 새로 쓰기 때문에
한 쪽만 재면 나머지 쪽의 스크롤값이 지워집니다. 재는 곳은 늘 실기 폴더라
진짜 이미지·글꼴 위에서 잰 값이 나옵니다. 덮어쓰기 전 `_backup/measure/` 에 남깁니다.

## 고친 코드가 안 돌 때 — 묵은 껍데기(.pyc)

파이썬은 `.py` 를 처음 읽을 때 `__pycache__` 에 `.pyc` 를 만들어 두고,
다음부터는 원본의 **(수정시각, 크기)** 가 그때와 같으면 `.py` 를 아예 읽지 않습니다.

이 폴더는 연결된 폴더라 수정시각이 오갈 때 흔들립니다.
그래서 원본을 고쳐도 파이썬이 "그대로네" 하고 묵은 `.pyc` 를 계속 쓰는 일이 생깁니다.
`read_gen.py` 에 `only` 를 넣었는데도 예전 `build()` 가 불려
`build() got an unexpected keyword argument 'only'` 가 난 것이 이 경우였습니다.

이제 `runner.py` 가 알아서 막습니다.

* 새 `.pyc` 를 만들지 않습니다 (`sys.dont_write_bytecode`)
* 시작할 때와 레시피를 부를 때마다 **어긋난 `.pyc` 를 치웁니다**
  (지울 수 없으면 앞머리를 지워 못 알아보게 만듭니다 — 그러면 원본에서 다시 읽습니다)
* 화면이 떠 있는 동안 `.py` 를 고쳐도 **원본에서 다시 읽습니다** (`refresh_modules`)

그래도 어긋나면 생성기를 끝내고 `__pycache__` 폴더를 지운 뒤 다시 여세요.

`app.log` 에 시작할 때마다 실제로 불려 온 파일과 `build()` 의 모양이 남습니다.

    2026-09-16 16:29  시작 http://127.0.0.1:8765
    2026-09-16 16:29    read_gen E:\...\read_gen.py  build(lesson=None, out=None, only=None)

여기 `only` 가 안 보이면 묵은 껍데기를 물고 있는 것입니다.

## 폴더 구조 (2026-09-17 정리)

```
_딕테이션_생성기/
├─ HTML생성기.vbs          두 번 눌러 실행
├─ app.py  app_page.py     화면
├─ runner.py  recipes/     껍데기와 레시피
├─ read_*.py               생성 엔진 (검증된 것 — 함부로 고치지 않는다)
├─ layout_io.py  layout_edit.py  rules_io.py  proto_scan.py  regress.py
├─ settings.json           자료 경로
├─ project.json            이 프로젝트의 단원 목록      ← 새로 생김
├─ 단원자료/               data<N>.py · 잰 값 · layout<N>.json
├─ rules/                  프로토 분석 결과 · 확정 규칙
├─ _기준본/                회귀 검사 기준
├─ _backup/                산출물 · layout · 잰 값 백업
└─ 문서/                   기록 문서
```

**개발물 폴더에는 완성본만 남습니다.** 백업은 `_backup/산출물/<레시피>/<단원>/<날짜시각>/`
로 뜨고, 잰 값은 `단원자료/` 에 씁니다. 되돌리기는 예전 자리도 함께 봅니다.

## project.json — 단원 목록

단원 수와 이름은 교재마다 다릅니다(1~5단원, 1~8단원 + Special Lesson, …).
코드에 박지 않고, **사용자가 지정한 두 폴더 안에서만** 찾아 `project.json` 에 적어 둡니다.

```
스토리보드 폴더의 '… Lesson 7.xlsx' · '… Special Lesson.xlsx'
산출 폴더(contents)의 'lesson07/ops' · 'special_lesson/ops'
```

한 번 적힌 뒤로는 이 파일이 기준입니다 — **사람이 고칠 수 있습니다.**
새 단원이 생기면 다음에 열 때 자동으로 더해지고, 이미 적힌 것은 손대지 않습니다.
경로는 프로젝트 폴더 기준 상대 경로라 다른 PC 로 옮겨도 그대로 씁니다.

    {"cj_reading": {"units": [
      {"id": "7",              "name": "7단원",         "storyboard": "…", "ops": "…"},
      {"id": "special_lesson", "name": "Special Lesson", "storyboard": "…", "ops": "…"}
    ]}}

화면의 단원 칸에도 이 이름이 그대로 나옵니다.
